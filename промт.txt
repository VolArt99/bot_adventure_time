# Промт проекта: Bot Adventure Time (детализированный)

Рабочий контекст для разработчика/агента. Цель: быстро понять архитектуру, правила и ожидания по качеству.

---

## Роль и цель

Ты — senior Python/aiogram инженер, который:
1. Поддерживает стабильность прод-бота на VDS (Docker Compose + PostgreSQL).
2. Вносит улучшения без поломки пользовательских сценариев.
3. Сохраняет документацию в актуальном состоянии.

Definition of Done:
- код работает;
- `pytest -q` зелёный;
- обновлены `README.md`, `промт.txt` и при необходимости `deploy/VDS_SETUP.md`;
- пользовательские тексты — через `bot/utils/design.py`, не хардкод в handlers.

---

## Продуктовый контекст

Бот для приватного Telegram-сообщества (супергруппа с Topics / форум).
Задачи: мероприятия, участие, напоминания, дайджесты, random 1:1, онбординг, split bill, пожертвования на поддержку бота.

### Пользовательские потоки
1. `/start` → онбординг → одобрение владельцем → вход в группу.
2. `/create_event` в ЛС → превью → публикация карточки в тему; `/edit_event` — правка полей после публикации.
3. Участники: `✅ В путь!` / `⏳ В резерве` / `❌ В другой раз`.
4. Напоминания (APScheduler) + weekly digest.
5. `/donate` — ссылки на сборы (доступно и не-участникам).
6. Админы: отчёты, темы, random-пары, sync members, контроль «Рассказа о себе».

---

## Технологии

- Python 3.10+
- aiogram 3.x
- PostgreSQL 16 (asyncpg pool)
- APScheduler
- Docker Compose, long polling (`python -m bot.main`)
- Опционально: OpenWeatherMap (`WEATHER_API_KEY`)

**Не используется:** YDB, Cloud Functions, webhook entrypoint.

## Карта репозитория

### Корень
- `docker-compose.yml`, `Dockerfile` — VDS-деплой (лимиты RAM, тюнинг PG)
- `deploy/` — `deploy.sh`, `backup_db.sh`, `postgresql.vds.conf`, `VDS_SETUP.md`, systemd unit
- `.env.example` — шаблон env
- `README.md`, `промт.txt` — документация
- `tests/` — pytest

### `bot/`
- `main.py` — polling, lazy init, error handler → owner
- `config.py` — env, роли, лимиты, donate URLs
- `commands.py` — реестр `COMMAND_SPECS`
- `database.py` → `database_pg.py` — вся работа с БД
- `db_pool.py` — asyncpg pool
- `fsm_storage_pg.py` — FSM в таблице `fsm_states`
- `texts.py` — карточки событий, дайджесты, напоминания
- `keyboards.py` — inline-клавиатуры
- `utils/design.py` — **BRAND_VOICE**, **SEASON_COPY**, **WIZARD_PROMPTS**, визуальные helpers

### Handlers
- `common_feature/` — start, help, menu, status, donate, onboarding, approve/reject
- `event_scenarios/` — FSM create/edit/category/carpool
- `participation.py` — join/waitlist/decline, carpool
- `split_bill_feature/` — split bill FSM + карточка
- `digest.py`, `subscriptions.py`, `my_events.py`, `roadmap.py`, `admin.py`

### Middleware / filters
- `command_access.py` — роли и лимиты в ЛС
- `topic_discoverer.py` — автообнаружение тем форума
- `latency_metrics.py` — p50/p95/p99

## Брендинг и тексты

**Источник правды:** `bot/utils/design.py`

- `BRAND_VOICE` — фразы бота (меню, онбординг, участие, статусы)
- `SEASON_COPY` — сезонные слоганы (зима/весна/лето/осень)
- `WIZARD_PROMPTS` — шаги мастера `/create_event`
- `brand_voice(key)`, `season_copy(key)`, `wizard_prompt(key)`

Тон: приключенческий (Adventure Time community), без персонажей мультсериала.

При изменении UX:
1. Обновить словари в `design.py`
2. Синхронизировать `common_feature/views.py`, `texts.py`, help
3. Обновить тесты в `tests/test_help_text_html.py`, `tests/test_texts.py`

## Актуальные UX-детали

- Кнопки карточки: `✅ В путь!`, `⏳ В резерве`, `❌ В другой раз`
- Превью: кнопка `🗺️ Публикуем!`
- `/menu`: сезонная шапка, слоган «Куда отправимся сегодня?»; `/help` и кнопки меню синхронизированы с `commands.py`
- Карточка мероприятия: **Hero + детали** (без дублирования категорий/цены); погода в день события
- Быстрые шаблоны: выбор «оставить из шаблона» / «ввести своё» для названия и описания
- Мастер событий: «↩️ Назад» на шагах темы, категорий и превью
- Split-bill: `money_collection_line` + чек-лист ✅/⏳
- `/donate` в разделе «Помощь» меню + команда; outsider: `start,donate`
- `@username` в admin-командах — резолв через БД + approved members
- `/send_event_card` — короткое сообщение со ссылкой, не дубль карточки
- `/random_pairs` — общая карточка в topic, без ЛС участникам
- FSM в ЛС: `answer_private_intermediate` / `answer_private_final`
- Callback policy: `CALLBACK_DELETE_WIZARD_MESSAGE` только для wizard

## Роли и доступ

- **Owner** — полный доступ
- **Admin** — расширенный, с лимитами
- **Approved member** — пользовательские команды
- **Outsider** — `start`, `donate` (по умолчанию)

Центр: `middleware/command_access.py` + `config.py` + `bot/commands.py`

---

## Правила разработки

1. Не ломать совместимость команд без migration-плана.
2. SQL только параметризованный (asyncpg).
3. HTML — экранировать пользовательский ввод.
4. HTTP — timeout + exception handling.
5. Бизнес-логику не дублировать — shared/services/utils.
6. Нетривиальные сценарии — тест.
7. Изменил UX → `design.py` + help + README + промт + тесты.
8. Новые фразы — в `BRAND_VOICE`, не в handlers.
9. Не коммитить секреты (.env, токены).

## Деплой (VDS)

См. `deploy/VDS_SETUP.md` и раздел README «Деплой на VDS».

Кратко:
```bash
cp .env.example .env
# BOT_TOKEN, GROUP_ID, OWNER_ID, POSTGRES_PASSWORD, DONATION_* ...
docker compose up -d --build
```

PostgreSQL: `deploy/postgresql.vds.conf`, лимит 768M. Бот: 512M.

## Частые ошибки

1. **FSM завис** — onboarding_guard, middleware, state filters
2. **Не публикуется в тему** — права бота, `message_thread_id`, GROUP_ID
3. **Нет данных в БД** — DATABASE_URL, postgres healthy, AUTO_INIT_DB
4. **Команда недоступна** — allowlist, approved_member, лимиты
5. **/donate без кнопок** — не заданы DONATION_SBERBANK_URL / DONATION_TBANK_URL
6. **Тексты разъехались** — забыли обновить `design.py` и help
