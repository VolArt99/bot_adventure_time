Рабочий контекст для разработчика/агента. Цель: быстро понять архитектуру, правила и ожидания по качеству.

## Продуктовый контекст

Бот для приватного Telegram-сообщества (супергруппа с Topics / форум).
Задачи: мероприятия, участие, напоминания, дайджесты, случайные встречи 1:1, онбординг, split bill («скинуться»), пожертвования на поддержку бота.

### Пользовательские потоки
1. `/start` → онбординг → одобрение владельцем (`approve_user_*`) → invite-ссылка → вход в группу → запись в `approved_members`.
2. Участник **в Telegram-группе без одобрения бота** не получает команды участника (авто-добавление в `approved_members` отключено).
3. `/create_event` в ЛС → дата/время отдельно, опциональная ссылка, длительность (`1 ч 30 мин` / уточнение единиц) → превью → публикация; push подписчикам категории; `/edit_event` — правка полей (в т.ч. ссылка).
4. Участники: `✅ В путь!` / `⏳ В резерве` / `❌ Снять запись`; переключение резерв↔основной одним нажатием; `👥 Гости` (ЛС → число → `@user + N гостя`); `🚗 Ищу попутку`; подтверждение участия за 24 ч до события; сводка явки организатору в `/my_events`.
5. Напоминания (APScheduler) + weekly digest + restore jobs после рестарта; empty-alert организатору при 0 участниках; monthly re-engage owner.
6. `/my_events` → «📋 Копия #ID» — шаблон из прошлого мероприятия; кнопка «✅ Явка».
7. `/donate` — ссылки на сборы (доступно и не-участникам).
8. Админы: отчёты, темы, random-пары, sync members, контроль «Рассказа о себе», `/refresh_event_cards` (пакетно обновить кнопки/текст будущих карточек).
9. `/set_birthday ДД.ММ` → ежедневный пост-поздравление в тему «Общение и не только».
10. В тихие часы ЛС ставятся в `pending_notifications` и отправляются после `QUIET_HOURS_END`.

## Технологии

- Python 3.10+
- aiogram 3.x
- PostgreSQL 16 (asyncpg pool)
- APScheduler
- Docker Compose, long polling (`python -m bot.main`)
- Опционально: OpenWeatherMap (`WEATHER_API_KEY`)

**Не используется:** YDB, Cloud Functions, webhook entrypoint, таблица `reminder_jobs`.

## Брендинг и тексты

**Источник правды:** `bot/utils/design.py`

- `BRAND_VOICE` — фразы бота (меню, онбординг, участие, статусы)
- `SEASON_COPY` — сезонные слоганы (зима/весна/лето/осень)
- `WIZARD_PROMPTS` — шаги мастера `/create_event`
- `brand_voice(key)`, `season_copy(key)`, `wizard_prompt(key)`

Тон: приключенческий (Adventure Time community), без персонажей мультсериала. **Единый регистр «ты»** во всех пользовательских текстах.

При изменении UX:
1. Обновить словари в `design.py` (`BRAND_VOICE` — не хардкод в handlers)
2. Синхронизировать `common_feature/views.py`, `texts.py`, help
3. Обновить тесты в `tests/test_help_text_html.py`, `tests/test_texts.py`
4. Обновить `README.md` и этот `промт.txt`

## Актуальные UX-детали

### Меню (`/menu`)
- Шапка: **«Центр приключений»** + сезонный слоган; без длинного блока описаний кнопок.
- Разделы: 🎉 События · 🧾 Скинуться · 🔔 Уведомления · 🤝 Комьюнити · 🔴 Админ (3 подраздела: Люди / Контент / Система).
- Админ → Контент: **🔄 Обновить карточки** = `/refresh_event_cards` (пакетно обновить будущие карточки после деплоя).
- Подменю: одна кнопка **↩️ Назад**; `menu_cmd_*` — подсказки с префиксом **⌨️**; `menu_action_*` — реальные действия.
- Уведомления: подписки + **«🔕 Режим уведомлений»** (`notify_all` / `notify_mine` / `notify_off`).

### Участие и карточки
- Кнопки карточки: `✅ В путь!`, `⏳ В резерве`, `❌ Снять запись`, `👥 Гости`, `🚗 Ищу попутку`; в группе — **🤖 Открыть в ЛС**.
- В ЛС: основной состав — `⏳ В резерв` / `❌ Снять запись`; резерв — `✅ В путь!` / `❌ Снять резерв`.
- Переключение: резерв + «В путь!» → основной (если есть место); основной + «В резерв» → резерв (место уходит первому в очереди).
- `👥 Гости` → ЛС «сколько гостей?» → в списке `@user + N гостя`; гости входят в лимит мест; `0` снимает гостей.
- Резерв: toast «В резерве · ты №N…»; продвижение из резерва — брендовое ЛС (`waitlist_promoted`).
- Групповая карточка: CTA внизу «Запишись: В путь · Резерв · Снять запись» (`show_cta=True`).
- Карпулинг в ЛС: брендовые формулировки (`carpool_driver_seats`, `carpool_choose_driver` и т.д.).
- Неодобренный: alert `approval_required` при callback в группе.

### Онбординг
- Краткие правила + «📜 Полные правила» (структурированный мягкий текст).
- После одобрения: чеклист + кнопки **📣 Афиша** и **🏠 Открыть меню**.
- Одобрение: `🎉🗺️ Дверь открыта!`; контакт капитана на «ты».

### Прочее
- За `ATTENDANCE_CONFIRM_HOURS` (по умолчанию 24) до события — ЛС «Ты всё ещё идёшь?» с кнопками confirm/decline
- `/my_events`: «📋 Копия #ID» → мастер создания с предзаполнением
- Превью: кнопка `🗺️ Публикуем!`
- `/help` и кнопки меню синхронизированы с `commands.py` (включая описание кнопок: гости, карпулинг и т.д.)
- Карточка мероприятия: **Hero + детали**; опциональная ссылка; погода в день события; Google Календарь (не «GCal»)
- Мастер `/create_event`: дата и время отдельно; длительность `1 ч 30 мин` / уточнение единиц; опциональная ссылка
- Быстрые шаблоны: «оставить из шаблона» / «ввести своё»
- Мастер событий: «↩️ Назад» на шагах темы, категорий и превью
- Split-bill: `money_collection_line` + «осталось собрать X ₽»; отмена — `split_bill_cancel`
- Комьюнити: toggle «Случайные 1:1 · вкл/выкл»; день рождения — одна кнопка → подменю
- Дневной лимит: `command_limit_member` / `command_limit_admin` в `BRAND_VOICE`
- `/donate` в разделе «Помощь»; outsider: `start,donate`
- `@username` в admin-командах — резолв через БД + approved members
- `/send_event_card` — короткое сообщение со ссылкой, не дубль карточки
- `/send_events_list`, `/digest`, `/my_digest` — учитывают `period_end`; ссылки `t.me/c/<chat>/<thread>/<msg>`
- `/random_pairs` — общая карточка в topic, без ЛС участникам
- FSM в ЛС: `answer_private_intermediate` / `answer_private_final`
- Callback policy: `CALLBACK_DELETE_WIZARD_MESSAGE` только для wizard
- ЛС в тихие часы → `pending_notifications` → flush после `QUIET_HOURS_END`
- Push подписчикам: `category_notify` + фильтр `notification_kind` (`broadcast` / `personal`)
- Участники: UNIQUE + capacity в SQL; ID через sequences
- Явка: сводка в `/my_events` + кнопка «✅ Явка»
- Empty-alert организатору при 0 участниках за 24ч; monthly re-engage owner 1-го числа
- Дни рождения: set/birthday/clear + daily post в «Общение и не только»
- Правила: `get_group_rules_text()` с `OWNER_CONTACT`, мягкая структура

## Роли и доступ

- **Owner** — полный доступ (`OWNER_ID`)
- **Admin** — расширенный, с лимитами (`ADMIN_IDS`)
- **Approved member** — запись в `approved_members` (после `approve_user_*` или уже существующая); пользовательские команды из `MEMBER_ALLOWED_COMMANDS`
- **Outsider** — `start`, `donate` (по умолчанию)

**Не путать:** членство в Telegram-группе ≠ approved member. Авто-upsert при вступлении в группу отключён.

Центр для ЛС: `middleware/command_access.py` + `config.py` + `bot/commands.py`
Групповые callback: проверки в хендлерах (`@approved_member_callback_only`, `_can_manage_event`, `_can_view_event`).

Дневные лимиты в PostgreSQL (`user_command_usage_daily`), действуют на команды и callback в ЛС.

## Правила разработки

1. Не ломать совместимость команд без migration-плана.
2. SQL только параметризованный (asyncpg).
3. HTML — `html.escape()` для пользовательского ввода (события, split bill, админ-ответы).
4. Callback `data` — `parse_callback_suffix_int` / `parse_callback_split_int`, не голый `int(split(...))`.
5. HTTP — timeout + exception handling.
6. Бизнес-логику не дублировать — shared/services/utils.
7. Новый домен БД — отдельный модуль в `bot/db/`, экспорт через `bot/db/__init__.py`.
8. Нетривиальные сценарии — тест (`test_security_helpers.py`, `test_access_and_flows.py`).
9. Изменил UX → `design.py` + help + README + промт + тесты.
10. Новые фразы — в `BRAND_VOICE`, не в handlers.
11. Не коммитить секреты (.env, токены).
12. Групповые callback — явная проверка прав; не полагаться на `CommandAccessMiddleware`.

## Деплой (VDS)

См. `deploy/VDS_SETUP.md` и раздел README «Деплой на VDS».

Кратко:
```bash
cp .env.example .env
# BOT_TOKEN, GROUP_ID, OWNER_ID, POSTGRES_PASSWORD, DONATION_* ...
docker compose up -d --build
docker compose ps   # health: postgres + bot
```

PostgreSQL: `deploy/postgresql.vds.conf` + `deploy/pg_hba.docker.conf`, лимит 768M. Бот: 512M. **Не публиковать** 5432 на хост.

Бэкапы:
```bash
./deploy/backup_db.sh   # chmod 600 на .sql.gz и .sha256
./deploy/verify_backup.sh backups/adventure_time_*.sql.gz
./deploy/restore_db.sh backups/adventure_time_*.sql.gz   # осознанный откат
```
Cron-пример: `deploy/backup-cron.example`, retention: `BACKUP_RETENTION_DAYS`. Дамп содержит PII — хранить с ограниченным доступом.

## Частые ошибки

1. **FSM завис** — onboarding_guard, middleware, state filters
2. **Не публикуется в тему** — права бота, `message_thread_id`, GROUP_ID
3. **Нет данных в БД** — DATABASE_URL / PG*, postgres healthy, AUTO_INIT_DB
4. **Команда недоступна** — allowlist, `approved_members`, лимиты (в т.ч. callback в ЛС)
5. **В группе, но бот не пускает** — нет записи в `approved_members`; нужен `approve_user_*`
6. **/donate без кнопок** — не заданы DONATION_SBERBANK_URL / DONATION_TBANK_URL
7. **Тексты разъехались** — забыли обновить `design.py` и help
8. **iOS: ссылка на карточку открывает группу** — в `build_event_message_link` нужен `thread_id` темы; перепубликовать афишу после фикса
9. **bot unhealthy** — heartbeat не обновляется; смотреть `docker compose logs bot`, `BOT_HEARTBEAT_PATH`
10. **ImportError из bot.database** — символ не в `bot/db/__init__.py` `__all__`
11. **Резерв сдвинулся без отказа** — проверить `decline_*`: `move_from_waitlist` только если `remove_participant` вернул True
